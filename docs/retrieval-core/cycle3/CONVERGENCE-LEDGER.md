# First-layer convergence ledger

The evidence does **not** select a new universal first layer. Retain shared-core
matching and human Work identity while Opus decides the task interaction. This is
a bounded conclusion, not a request for another open-ended ranking cycle. All new
selection code is isolated in `GleanerRetrievalExperiments`; the app, CLI and MCP
do not invoke it. No production search, corrections schema or provider adapter
changed in this cycle.

## Resolved by executed evidence

| Question | Evidence and resulting boundary |
|---|---|
| Does context diversity solve the observed first-layer problem? | No demonstrated gain: selected objects equal baseline in all eight independently labeled tasks. The rehearsal case still defers both useful objects. Retain as an ordering option, not the default recommendation. |
| Does requiring explicit task scope provide a better default? | Not established. It requests clarification in 4/8 tasks, including one uniquely matching corrected Work. Three extra-term queries help all policies equally. Additional input is useful; forcing it is an interaction cost. |
| Is selection equivalent to suppression or grouping? | No. All 24 policy responses retain a disjoint selected/deferred/unmatched partition of raw Work IDs. Human-joined representations remain one Work. Raw wanted Work/representation reachability is 100%, but that does not cure first-layer or approved-state misses. |
| Can task labels call scripts or intermediate files useful? | Yes. The independent rehearsal task requires two complementary outputs; the equal-input reproduction task requires both a review and a script. No extension blacklist or automatic “final” classification was introduced. |
| Does approved Work selection locate its approved representation? | Not necessarily. Checking only the matched rendition excludes a joined Work whose other rendition has approved bytes. Its recoverability through unmatched results is not successful approved-state retrieval. |
| Do corrections survive actual rereading and alter selection? | Yes in the tested boundary: all three held-out logs reread, and four development logs survive changed-source reread, cursor invalidation and test-only log-projection reconstruction. Project/collection corrections change matches 0→2 / 0→1 across all policies and remain effective. |
| May every persisted observation be discarded as derived index state? | No. An unsafe synthetic deletion of native observations loses a kept missing Work despite retained review/correction rows. Safe reconstruction retains observations, spans and captures; this is not a public reset API. |
| Are current files and indexed deliveries interchangeable discovery universes? | No. The equal-input directory comparator finds a new current file with no delivery after indexing; shared-core search does not. That is admission/freshness scope, not evidence that changing rank alone solves discovery. |
| Has a model become necessary? | No. No demonstrated ambiguity here justifies a mandatory model, paid service or new credentials. Deterministic matching/refinement remains the bounded implementation basis. No semantic arm was executed. |

The held-out comparator's known-basename/directory traces are ideal navigation
lower bounds with stronger location knowledge. A separate four-task development
comparator gives both arms the same authorized project and literal terms, executes
actual path/body searches versus actual shared CLI queries, and opens every first
five result before scoring. It is still not a human or Finder trial. Directory
reads current bytes; CLI reads exact captured bytes. See [EVALUATION](EVALUATION.md)
and [directory comparison](DIRECTORY-COMPARISON.md).

## Requires Opus product judgment

1. **Default interaction:** show actionable objects immediately with a visible
   remainder, show a neutral context overview, or ask when intent is genuinely
   ambiguous. The tested unconditional question gate is too broad to recommend.
   A context overview must be labeled as navigation, not relevance or authority.
2. **Discovery scope:** decide whether unkept observations and newly found current
   files are searchable by default. Preserve explicit-delivery versus observation
   evidence and incomplete-index status if scope broadens. Rank cannot retrieve
   objects absent from the admitted candidate universe.
3. **Version and representation choice:** define whether “approved” selects the
   matched capture or searches approved representations of a Work. Never equate
   current disk bytes, latest delivered bytes, approved bytes, published bytes and
   an authoritative working version without evidence.
4. **Public interface:** choose shared human/agent semantics before exposing
   selection policies. The experiments' full raw/eligible/remainder arrays and
   overview are unbounded; their selected limit alone is not a pagination contract.

No product ruling is inferred from benchmark labels. No acceptance, later ruling,
identity merge or working-version authority is invented. Current-original and
report-local exact-ID proposals from [cycle 2](../cycle2/DECISION-NOTE.md) remain
separate implementation candidates; this cycle does not integrate them.

## Bounded next implementation boundary

Stop ranking experimentation at this checkpoint. Preserve the actual shared search,
raw discoverability and durable user decisions. If Opus authorizes a next build,
choose a concrete discovery/representation interaction and its success criterion;
then implement that through shared core and thin adapters. Independently review
the existing current-original and scoped report-ID proposals, their migration and
pagination contracts, and native receipts before adoption. Do not merge experiments
or expand schema merely because their tests execute.
