# Retrieval-core source index

Reviewed 2026-10-19. Primary sources only. These are mechanism references, not evidence that Gleaner passes a benchmark or that a foreign application was executed. Public documentation was read in the browser; repository contracts were inspected at `2648094610facfd1ae1805f52a9de282043c808f`.

| ID | Source | Supported observation | Transfer and limit |
|---|---|---|---|
| S1 | [Apple, App Search Programming Guide: Index App Content](https://developer.apple.com/library/archive/documentation/General/Conceptual/AppSearch/AppContent.html), archived guide, updated 2016-12-15 | Searchable items have unique identifiers, optional grouping domains, descriptive metadata and an action that restores item context. Index maintenance includes updates, deletion and restartable batches. | Index an actionable object with its context. This historical guide is not a current scale recommendation or a reason to replace Gleaner's local registry with Spotlight. |
| S2 | [Zotero, Duplicate Detection](https://www.zotero.org/support/duplicate_detection) | Detection proposes duplicates within a library; the person performs a merge, which retains organizational information. Separate libraries remain separate. | Keep candidate equivalence distinct from accepted identity. Do not import bibliographic heuristics into arbitrary artifacts. |
| S3 | [Zotero, Adding Items](https://www.zotero.org/support/adding_items_to_zotero#standalone_attachments_and_parent_items) | A parent item and its file attachments are different objects; weak metadata can leave an attachment standalone. | A logical object need not be a file, and absent metadata should remain absent. Automatic metadata retrieval for academic papers does not establish reliable classification of arbitrary generated files. |
| S4 | [W3C, PROV-DM](https://www.w3.org/TR/prov-dm/), Recommendation 2013-04-30 | Entities, activities and agents are distinct; generation, usage, derivation, attribution, communication, revision and collection membership are separate relations. | Preserve the distinction between an observed write, a delivered artifact and a later decision. Use the vocabulary as a conceptual check, without introducing RDF or a graph engine. |
| S5 | [SQLite, FTS5](https://www.sqlite.org/fts5.html), especially sections 4.4, 5.1 and 6.12 | FTS5 provides weighted-column BM25, bounded snippets and an index rebuild operation. External-content tables require the application to maintain consistency. Smaller BM25 values rank better in SQLite. | A possible acceleration layer when measured scale needs it, not a second CLI-only search engine. Query syntax, tokenization, synchronization and migration need tests before adoption. |
| S6 | [Thakur et al., BEIR](https://arxiv.org/abs/2104.08663), 2021 | Evaluation spans heterogeneous retrieval domains; lexical BM25 remains a robust baseline, while stronger average reranking results carry computational cost. | Compare diverse tasks and report per-family failures. The paper does not establish the best method for this artifact corpus or justify a mandatory model dependency. |
| S7 | [Git, git-worktree](https://git-scm.com/docs/git-worktree) | A repository can have a main worktree and linked worktrees with separate checkout locations and per-worktree administrative state. | Keep checkout and repository evidence distinct; a product-level project mapping is another decision. Do not infer project meaning solely from branch names. |
| S8 | [The Open Group, realpath](https://pubs.opengroup.org/onlinepubs/9799919799/functions/realpath.html), POSIX.1-2024 | Filesystem resolution removes symbolic-link and dot components and can fail when resolution is unavailable. | Lexical normalization and filesystem authorization are different operations. Preserve the written locator; containment must be checked against authorized roots when resolving existing candidates. |
| S9 | [MCP, 2026-07-28 base protocol](https://modelcontextprotocol.io/specification/2026-07-28/basic) | Modern requests carry required protocol-version and client-capability metadata independently; results include a result type. | Do not label Gleaner's legacy SDK flow as implementing this revision. |
| S10 | [MCP, 2026-07-28 stdio](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/stdio) | Stdio uses newline-delimited JSON-RPC, reserves stdout for protocol messages, and documents discovery probing followed by legacy initialization fallback. Modern cancellation has stricter response rules. | Preserve framing and verify actual negotiated behavior. A compatible legacy server is not a modern-protocol server. |
| S11 | [MCP, 2025-11-25 lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle) and [cancellation](https://modelcontextprotocol.io/specification/2025-11-25/basic/utilities/cancellation) | This revision uses initialization/version negotiation. Receivers may ignore cancellation when a request cannot be cancelled. | These are the relevant contracts for the currently pinned Swift SDK and existing host tests. |
| S12 | [MCP, 2025-11-25 tools](https://modelcontextprotocol.io/specification/2025-11-25/server/tools) | Tools have schemas, annotations, structured content and tool-level errors; annotations are hints rather than an authorization boundary. | Keep read-only tools truthful; existing handoff writes a cache copy and must remain marked as a write. |
| S13 | [MCP, 2026-07-28 pagination](https://modelcontextprotocol.io/specification/2026-07-28/server/utilities/pagination) | Protocol list operations use opaque cursors and a server-controlled page size. | Search-result pagination inside a tool is an application contract. Reuse the principle but do not claim MCP requires a particular search cursor schema. |
| S14 | [Official Swift MCP SDK release 0.12.1](https://github.com/modelcontextprotocol/swift-sdk/releases/tag/0.12.1) | The release exists independently of the later specification. | Gleaner's `Package.resolved`, adapter and wire tests are the evidence for what this build actually uses; a package release page alone is not protocol execution. |
| S15 | [Anthropic, Contextual Retrieval](https://www.anthropic.com/engineering/contextual-retrieval), 2024-09-19 | Isolated passages can lose the document context needed to retrieve them; the reported system adds context before lexical/vector indexing and reranks retrieved candidates. Exact identifiers remain an important lexical case. | Reuse native project, heading and turn context first. Its generated context, commercial models, benchmark gains and chosen candidate counts are not requirements or measured Gleaner results. |
| S16 | [Günther et al., Late Chunking](https://arxiv.org/abs/2409.04701v3), revised 2025-07-07 | Embedding a long context before pooling passage vectors can preserve contextual information that independent passage encoding loses. | This motivates preserving context across retrieval boundaries; it does not justify replacing native message/section boundaries or adding a large embedding model now. |
| S17 | [Microsoft, parent-child index projections](https://learn.microsoft.com/en-us/azure/search/search-how-to-define-index-projections) | Child search documents can retain parent identifiers and metadata; the indexing projection explicitly controls whether parents are also indexed. | Model the relationship once and avoid duplicated parent/child results. Gleaner's SQLite joins and native evidence make the service's denormalization advice optional. |
| S18 | [Microsoft, vector query filters](https://learn.microsoft.com/en-us/azure/search/vector-search-filters) | Applying scope filters only after a global top-k can omit relevant scoped results, even returning zero despite available matches. | Apply authorized/project/source scope before candidate truncation in every retrieval arm. HNSW-specific performance claims do not transfer to the current core. |
| S19 | [Elastic, reciprocal rank fusion](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/reciprocal-rank-fusion) | Rank fusion combines independently ranked candidate lists without directly comparing their raw score scales. Its candidate window affects cost and result quality. | An optional way to compare lexical and semantic candidates; preserve object identity and scope before fusion. No Elasticsearch deployment is proposed. |
| S20 | [Microsoft, changed and deleted blob indexing](https://learn.microsoft.com/en-us/azure/search/search-how-to-index-azure-blob-changed-deleted) | Change detection and deletion detection are separate indexing concerns, with source keys and a deletion policy affecting correctness. | Rebuild derived records from stable source anchors and explicitly track source health; do not transfer blob deletion semantics to durable captures or user corrections. |
| S21 | [Liu et al., Lost in the Middle](https://arxiv.org/abs/2307.03172v3), 2023 | In the studied models/tasks, information position and long distractor contexts affect answer performance. | Measure progressive expansion and distractor burden, not only retrieved bytes. This is historical evidence, not a claim about every current model. |
| S22 | [Microsoft, RAG design and evaluation guide](https://learn.microsoft.com/en-us/azure/architecture/ai-ml/guide/rag/rag-solution-design-and-evaluation-guide), updated 2026-06-30 | Recommends representative media, uncovered queries, structure-sensitive segmentation, separate stage evaluation and end-to-end evaluation. | Separate capture, retrieval, context utility and task success. Use deterministic labeled fixtures before any optional model-assisted evaluation. |
