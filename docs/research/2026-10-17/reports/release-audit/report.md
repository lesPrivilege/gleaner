## Ranked domain defects

**D1 · P1 — A changed path type can replace the selected saved file with a live folder.** `Sources/GleanerCore/Library.swift:227–235` returns `.folder` before checking the selected delivery's hash/saved copy when either the current path is a directory or any selected capture was a directory. Scenario: deliver and save `report.md`, replace that path with a directory, select the old delivery. Preview/Open/drag now use the directory (`DetailView.swift:120–122,341–343`; `LibraryModel.swift:189–192`), even though the old file is preserved. The inverse also enables folder handoff after a delivered folder is missing or replaced by a file. Evidence: direct branch trace and proposed Swift regression cases. Minimal repair: decide from the selected capture first; a regular-file delivery resolves its hash regardless of today's path kind. Offer live-folder actions only for a selected folder that still exists as a directory; require an explicit choice for a replacement.

**D2 · P1 — An incomplete reread can sever preserved history.** `SessionLog.swift:51–65` tolerates malformed records; adapters return a successful partial log; `Indexer.swift:95–102,110–133` then prunes every delivery not reconstructed. `Registry.swift:75–83` deletes its capture too. Scenario: a previously indexed log is truncated/partially rewritten or an existing delivery record becomes malformed. Its saved object survives, but the delivery→hash association disappears. If the log is repaired after the original file is gone, the new capture is `never_observed`; the retained bytes are no longer discoverable through that delivery. This is not a claim that an ordinary incomplete appended tail deletes earlier valid records. Evidence: exact pruning SQL executed against a synthetic SQLite database removed both rows; a full adapter/indexer regression is supplied for Mac. Minimal repair: distinguish complete reconstruction from partial/failed parsing; preserve the prior committed interpretation/captures on incomplete input and report degraded coverage. Continue pruning genuinely rejected mentions after a certified complete reread.

**D3 · P1 — Compare does not always hold the exact bytes its header identifies.** `Comparison.swift:40–45` hashes an image path, then returns the same mutable URL; `ComparePane.swift:72–76` reads it later. `LibraryModel.swift:212–216` supplies the live source for “File on disk.” A writer between verification and image loading can therefore put new pixels under the old digest. Separately, `ComparePane.swift:54–57` publishes detached results without cancellation/request-key validation: a slow earlier comparison can replace a newer comparison's content. These are source-established race paths; no native race reproduction is claimed. Minimal repair: compare verified immutable staged ends (or owned image data), publish only for the requesting comparison key, and include source/provenance in that key. Carry “first seen later” into `compareEnd` labels (`LibraryModel.swift:198–206`); currently comparison drops that qualifier. Text comparison does rehash the actual data it diffs at `Comparison.swift:67–73` and is materially stronger.

**D4 · P2 — Project scoping loses repository distinctions and external-worktree history.** `Projects.swift:13–17` reduces repository identity to its final folder name, and `LibraryModel.swift:95–98,163–168` uses that string as the filter identity. Two distinct `/client-a/app` and `/client-b/app` repositories become one “app” scope. After an external worktree is deleted and the app relaunched, its `.git`/`commondir` evidence is gone: ascending paths cannot reconstruct the former repository. The existing test covers a nested worktree and reuses the process cache, not a cold restart for an external checkout. Evidence: path-resolution transcription over synthetic Git layouts demonstrated both cases. Minimal repair: keep an internal repository key separate from its short display name, and retain the last verified cwd/worktree→repository association with its observation basis. Unresolved historical context should stay explicit; this does not require manual filing or a project catalog.

**D5 · P2 — The offered historical Git restore command can select a commit without the file.** `Locator.swift:45–48` calls any path occurrence on any ref recoverable, but `DetailView.swift:347–353` always restores the parent of the latest touching commit. For a file added only on another branch, that parent lacks the file. A synthetic Git repository reproduced exit 1 although the candidate commit contained the file. Single-quote interpolation also produces invalid shell syntax for a normal path such as `Bob's Project` (shell syntax check exit 2). Minimal repair: find and verify a commit containing the blob, then safely quote a command naming that commit/path. Keep recovery user-operated and retain the warning that Git bytes may not be delivered bytes.

## Native application gaps

**N1 · P2 — Detached Quick Look can keep showing a different delivery from handoff.** `LibraryView.swift:28–29` updates `quickLookURL` only when artifact selection changes. Changing `chosenDelivery` or a query that selects another delivery of the same artifact does not update it; `LibraryModel.swift:224–226` only toggles the stored URL. Repro on Mac: open Quick Look for D1, choose D2 (or change the query to match D2), then compare the panel with the tile/Open/Copy. Minimal repair: derive panel content from an exact selection key and refresh after matching staging becomes ready, or deliberately close the panel on any version change. Returning focus belongs in this acceptance check.

**N2 · P2 — Clearing handoff copies strands the current selection.** `LibraryModel.swift:271–274,289` resets staging to idle and removes files; the preparation task in `DetailView.swift:46–52` is keyed only by artifact, delivery and observation time, none changed by Clear. Open/Copy/tile remain unavailable until the user changes selection or otherwise causes observation. A concurrent preparation can also complete into a cache being removed, and there is no retention policy for a receiver still consuming a staged path. Minimal repair: invalidate via an explicit generation and restage the active selection; coordinate cleanup with active preparation/consumption. Report cleanup failure instead of silently discarding it. Main source proves the missing restart; receiver lifetime is a native test, not a demonstrated failure here.

**N3 · P2 — Inaccessible or changed-format sources can look successfully empty.** `ClaudeCodeAdapter.swift:17–22` and `CodexAdapter.swift:31–34` convert enumeration failure into an empty inventory. `LibraryModel.swift:149–151` ignores `unknownRecordTypes`, including malformed-record counts. Settings says “Found” based on existence (`SettingsView.swift:12–15`); the empty state then says “No delivered files yet” (`LibraryView.swift:132–134`). Minimal repair: carry per-source complete/partial/unreadable diagnostics into one compact status with Retry; preserve usable cached results. Keep absence, access denial and unsupported input distinct. No new onboarding wizard or blanket Full Disk Access requirement is needed.

Other specific source findings and lower-priority decisions are in the appendix: co-delivery navigation loses the target occurrence; an unclosed code fence admits an example path; provider IDs lack a namespace; recovery actions provide weak failure feedback. They do not justify reviving previously rejected navigation systems.

## Problems worth solving next, with minimum support

| Problem → user benefit | Feasible capability and ownership | Minimum support → acceptance / tradeoff |
|---|---|---|
| “Which project was this from after the worktree disappeared?” → stable retrieval | Gleaner retains observed repository affiliation; person corrects only when evidence cannot resolve it | Repository key + label + historical location binding; two same-named repos stay distinct after cold restart. Later optional correction overlay costs reconciliation, not an ontology. |
| “I remember the report and chart from one request” → navigate the intended pair | Gleaner follows an exact co-delivery occurrence; later Thread/Timeline can expose existing evidence | Link carries artifact **and delivery** IDs; a reply/turn key handles multi-record Claude replies. Click a sibling from D1 and land on its D1, even if it has newer deliveries. No invented lineage. |
| “Can I trust these bytes?” → preview, compare and takeaway agree | Gleaner owns resolution, provenance and immutable prepared bytes; source app owns editing/regeneration | A selected-version/request key shared by preview, Compare and handoff; explicit unavailable/access-denied states; tests mutate sources and reverse completion order. |
| “Why is the thing I know I received missing?” → recover without guessing | Gleaner exposes source health and a bounded reason; original agent supplies omitted/remote artifacts | Scan completeness + failure cause + Retry; later optional hide/correct feedback should survive rescan. No requirement to rescan an entire codebase or claim full recall. |
| “I need this bundle elsewhere” → usable takeaway | Today explain single-file/folder limits; originating tool packages HTML dependencies or regenerates missing pieces | Later explicit member/version selection and a manifest, only if this job recurs. Check completeness separately from checksum validity; no dependency crawler implied. |
| “Review a long document, then return” → less context switching | Gleaner offers selected-byte preview/Open; source app owns full editing | Existing 64 KB limit plus explicit exact-version Open; optional Outline is already planned in PR #4. Local evidence navigation precedes generated summaries. |
| “Keep the library usable as it grows” → predictable wait/storage | Gleaner measures scan, query and staging cost before changing machinery | First-scan/cached-scan measurements, cancellation, bounded worker/output retention if warranted; optional FTS only after retrieval/scale measurements. Preserve captures separately from caches. |
