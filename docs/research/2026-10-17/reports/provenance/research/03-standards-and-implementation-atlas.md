# 3. Standards and implementation atlas

Public sources checked 2026-10-17. These are standards or first-party implementation documentation, not independent evidence that a particular deployment complies. Provider-specific evidence is in Part 4.

| ID and original source | Verified practice | Application and boundary |
|---|---|---|
| S01 [W3C PROV-DM, Recommendation, 30 April 2013](https://www.w3.org/TR/prov-dm/) | Entities, activities, agents, generation/usage/derivation, specialization, and bundles for provenance of provenance | A vocabulary for interchange. It neither verifies an assertion nor prescribes a database engine. Model a reconstructed representation and the reconstruction activity separately from the historical activity claimed |
| S02 [W3C PROV-CONSTRAINTS](https://www.w3.org/TR/prov-constraints/) | Companion constraints are explicitly linked by PROV-DM | Useful future consistency validation. This study verified the companion's identity via PROV-DM, not its full constraint rules; do not claim full PROV conformance from this report |
| S03 [OpenLineage object model](https://openlineage.io/docs/spec/object-model/) | Run, Job, Dataset; RunEvent plus design-time JobEvent/DatasetEvent; schema/version/lifecycle and other facets | Distinguish static declared lineage from run observations. Standard event structure is not proof a producer actually performed the reported write; generalized file artifacts need explicit mapping |
| S04 [OpenLineage facets](https://openlineage.io/docs/spec/facets/) | Extensible facets attach typed metadata to core objects | Borrow namespaced/versioned extension discipline. Do not make every message a job or imply the event contains historical dataset bytes |
| S05 [W3C DCAT 3](https://www.w3.org/TR/vocab-dcat-3/) | Catalog metadata distinguishes datasets and their distributions/access services, with versioning support | Good precedent for a catalog describing access to externally held material. Dataset/distribution semantics are not automatically the right artifact identity model |
| S06 [W3C Web Annotation Data Model](https://www.w3.org/TR/annotation-model/) | Bodies/targets, selectors and states; text quote, text position and byte-position selectors | An evidence pointer should identify both source representation and span. Text positions are brittle after edits; quote matching can be ambiguous and can disclose restricted text. Byte and normalized-character offsets are different |
| S07 [PREMIS Data Dictionary v3.0, June 2015, revised November 2015](https://www.loc.gov/standards/premis/v3/premis-3-0-final.pdf) | Objects, Events, Agents, Rights; event outcomes and relationships support migration/fixity/preservation records | Useful for transcode/export records and preservation-copy governance. Direct web fetch returned 403; public text was available through Exa search/fetch. Rights metadata is not an authorization enforcement service |
| S08 [WARC 1.1 specification](https://iipc.github.io/warc-specifications/specifications/warc-format/warc-1.1/) | Archive records, record identifiers, target URI/date, block/payload digests and conversion relationships | Pattern for separating original response, extraction, and derived representation. WARC storage does not guarantee all page dependencies, all authenticated views, or lawful disclosure |
| S09 [RFC 7089, Memento](https://www.rfc-editor.org/rfc/rfc7089) | HTTP framework for relating original resources to archived representations through datetime negotiation | Useful for URL version discovery where the server/archive supports it. A current URL plus requested time does not guarantee an archived representation exists |
| S10 [RFC 8493, BagIt](https://www.rfc-editor.org/rfc/rfc8493) | Package manifests, payload organization and checksum validation | Useful for an export's completeness/fixity manifest. A valid bag establishes package consistency, not that every payload was historically delivered or approved |
| I01 [DataHub stateful ingestion](https://docs.datahub.com/docs/metadata-ingestion/docs/dev_guides/stateful) | Ingestion checkpoints support comparisons between runs and optional stale-entity soft deletion | Mature reconciliation pattern. For Gleaner, absence from a scan should not erase historical evidence; restricted visibility, parser changes and partial scans differ from deletion. Connector defaults can differ from this generic guide |
| I02 [OpenMetadata lineage workflow, v2.0.x](https://docs.open-metadata.org/v2.0.x/connectors/ingestion/workflows/lineage) | Parse database query logs, view definitions or supplied query-log files after metadata ingestion | Concrete deployed counterexample to “all lineage requires new runtime instrumentation.” Retained logs and dialect/entity resolution determine coverage; SQL text alone is not a transaction-success receipt |
| I03 [Martin Fowler, Event Sourcing](https://martinfowler.com/eaaDev/EventSourcing.html) | Rebuild state from retained events; snapshots accelerate replay; external effects/queries complicate replay | Apply to the catalog's own decisions if useful. Arbitrary provider logs are not a complete event store. Replay interpretation as data; never rerun historical shell commands as recovery |
| I04 [Microsoft, Event Sourcing pattern](https://learn.microsoft.com/en-us/azure/architecture/patterns/event-sourcing) | Append-only events, projections, snapshots, ordering and schema-evolution considerations | A correction ledger with rebuildable views is one option. Full event sourcing is unnecessary if a small transactional database with an audit table meets the needs |
| I05 [Apache Iceberg schema evolution](https://iceberg.apache.org/docs/latest/evolution/) | Unique field IDs support add/drop/rename/reorder independently of field names or positions | Borrow stable field identity for adapter schemas. Renaming a field is not changing its meaning; reuse of old names must not resurrect old semantics. The live page identified latest as 1.12.0 when retrieved |
| I06 [Apache Avro 1.12.0 specification](https://avro.apache.org/docs/1.12.0/specification/) | Writer/reader schemas, resolution rules, defaults and aliases | Keep original schema/version with evidence and make normalization explicit. A reader default is not proof that the original source supplied a value; unknown and absent must remain distinguishable |
| I07 [Git cat-file](https://git-scm.com/docs/git-cat-file) | Object type/size/content retrieval by object name | Recover text or binary blobs without checking out or changing project files. A blob requires a repository/object-format context; a blob alone does not bind a path or delivery event |
| I08 [Git diff](https://git-scm.com/docs/git-diff) | Rename/copy detection uses configurable similarity and matching | Rename output is evidence of a comparison heuristic, not a stored move event or a logical-identity verdict |
| I09 [Git reflog](https://git-scm.com/docs/git-reflog) and [Git gc](https://git-scm.com/docs/git-gc) | Local reflogs and unreachable-object retention can expire; collection may prune objects | A hash is a stable identifier, not an availability promise. Do not assume a remote clone contains local reflogs or every dangling blob; never run collection or recovery mutations during read-only reconstruction |
| I10 [Linux inotify(7)](https://man7.org/linux/man-pages/man7/inotify.7.html) | Event queues, overflow/coalescing, and filesystem races affect watcher completeness | A watcher is a change hint, not a full byte archive. This source describes Linux, not macOS FSEvents; the general coverage concern must be checked against the actual platform |

All rows except the specifically qualified S02/S07 were opened through the web reader in addition to discovery where used. Access does not imply all source code or tests were audited. No external catalog service was provisioned or queried.

## What mature practice suggests

Use provenance vocabulary to make claims interoperable, catalogs to manage discovery and availability, preservation formats to identify retained representations, and an audit/correction mechanism for authored decisions. These concerns can coexist in ordinary tables and files.

There is a useful difference between **capture completeness**, **integrity**, **reconstruction determinism**, and **semantic confidence**. A digest checks byte equality after acquisition; it does not authenticate the origin. A signed record strengthens attribution/integrity under its trust model; it does not guarantee that its contents truthfully describe the world. An ACL governs access; it does not establish historical provenance. Combining these mechanisms requires explicit assumptions rather than collapsing them into one “verified” badge.

Source-preserving extraction should keep the source's identity and retrieval context, a stable evidence locator, extraction version, and the transformation into normalized fields. Preserve originals in place; retain only authorized local evidence or snapshots. OCR, Markdown conversion, transcript flattening, redaction, and summaries are derived representations with their own offsets and provenance, not replacements for the original evidence.
